# Remote engine (personal branch)

A model folder that is not a local model at all: every line is generated by an
HTTP service instead of sherpa-onnx. Everything else — presets, voice types,
cache, status, fallback — works as for any other model.

## Folder

```
Data\SKSE\Plugins\AudioUtilTTS\models\qwen-remote\
  remote.toml
  voices\malenord.wav          one recording per voice name
  voices\femaleeventoned.wav
```

`remote.toml`

```toml
url = "http://127.0.0.1:9880/tts"
timeout_ms = 20000      # one line, 1000..120000
sample_rate = 24000     # used until the answer's own rate is known
```

The recordings are the reference clips the service clones from. Voice numbers
are their place in name order, as on a Pocket model; a preset names one in
quotes:

```toml
[preset.malenord]
model = "qwen-remote"
voice = "malenord"
```

## HTTP contract

Request, `POST <url>` with `Content-Type: application/json`:

```json
{ "text": "你好，旅行者。", "voice": "malenord", "speed": 1.0, "format": "wav" }
```

Answer: `200` and a wav (PCM 8/16/24/32 or 32-bit float, any channel count,
mono preferred). Anything else is an error; the body is shown in the log when it
is short.

## Build

Cloud (no local Visual Studio):

1. Create an empty GitHub repository and push this folder to it.
2. The workflow `.github/workflows/build.yml` runs on every push and uploads
   `AudioUtilTTS-dll` with the DLL and `dist/`.
3. Copy the DLL over `mods\AudioUtilTTS ...\SKSE\Plugins\AudioUtilTTS.dll`.

Local: Visual Studio 2022 (v143, C++23) + xmake 3.0, then
`xmake f -m release -y` and `xmake -y`.

## Notes

- The service is contacted from the generation worker; a slow answer delays that
  line, it never blocks the game thread.
- A line that fails is reported in `AudioUtilTTS.log` with the service's answer.
- If the folder is the default model and the service is not up at game start,
  the plugin loads with no default model (`autts status` says why); starting the
  service and running `autts reload` fixes it without restarting the game.
